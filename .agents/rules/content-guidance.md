# Pedagogical Architecture Guidelines: Content Grounding and Cognitive UX

## 1. Academic Grounding Mandate

Every instructional module must anchor to an established behavioural science, cognitive psychology, or learning theory framework. Never present technical configuration steps in isolation; define the mental failure mode that makes the architectural constraint necessary.

* State the Cognitive Bottleneck: Identify the human working memory limit, decision heuristic, or operational failure point that the module addresses (such as Sweller's cognitive load, Kahneman's cognitive shortcuts, or Loewenstein's information gap).
* State the Mechanical Resolution: Explain precisely how the data schema, rule set, or arithmetic formula eliminates that cognitive failure.
* No Unsubstantiated Rules: Prohibit arbitrary rules or subjective design choices. Every constraint imposed on an AI agent or attendee must trace directly to a verified commercial risk or cognitive bias.

## 2. Macro-to-Micro Elaboration Architecture

Content delivery must follow Charles Reigeluth's Elaboration Theory to prevent cognitive fragmentation. Complex architectures must present the full operational system before isolating sub-components.

* Stage 1 (The Epitome Scaffold): Always render the complete, interconnected system model first. The audience must perceive all feedback loops, inputs, and final outcomes simultaneously to establish a global mental model.
* Subsequent Stages (Sequential Zoom): Break down individual loops, matrices, or formulas into dedicated sub-stages. Never introduce granular parameters until the global context is established.
* Progressive Micro-Staging: In Slide Mode, never display multi-column grids or comparative lists simultaneously during active lecturing. Isolate the single active card or concept at full opacity; unmount or hide subsequent stages until advanced by keyboard input to stop the audience from reading ahead of the spoken delivery.

## 3. The Conceptual-to-Operational Bridge

Theoretical presentation ("The Why") and technical assembly ("The How") must maintain strict structural parity.

* Direct File Counterparts: Every conceptual slide must map directly to an active file, data schema, or runtime script in Code Mode. A conceptual slide cannot exist without a code counterpart, and a code chunk cannot exist without prior conceptual grounding.
* Pinned Tactical Rationales: Every code chunk card rendered in Code Mode must carry an explicit, pinned card footer declaring its tactical rationale. Syntax must immediately connect to a concrete business threshold or operational outcome (for example: why a parameter exists, what breaks if omitted, or how it protects programmatic margin).
* Progressive Cognitive Fading: Follow Alexander Renkl's worked-example methodology. Begin with instructor-grounded models on slides, move to scaffolded pair-programming with character-by-character live streaming in Code Mode, and conclude with independent student execution during timed laptop sprints.

## 4. Subpixel Projector Stability and Visual Ergonomics

Digital projectors magnify small interface flaws. Interface design must eliminate visual noise in accordance with Richard Mayer's Coherence Principle.

* Zero Font Jitter: Never apply CSS `transform: scale()` to containers that hold typography during active, hover, or breathing animations. Scaling forces browser engines to recalculate subpixel font anti-aliasing on every animation frame, generating noticeable text shimmer across projector optics.
* Kinetic Accentuation: Express visual focus, breathing alerts, and spotlights strictly through CSS `box-shadow` depth and `border-color` transitions while locking the container to static dimensional bounds.
* Viewport Budgeting: Anchor all primary visual containers to an 84vh to 90vh viewport target using responsive CSS clamping (`clamp()`). Viewports must command 16:9 widescreen resolutions (1080p, 1440p, 4K) without letterboxing or horizontal overflow, and without forcing vertical page scrolling.
* Concise Wording: Keep card copy short and active. State the concrete physical item, rule, or action directly. Let the speaker provide spoken depth while the display supplies visual clarity.

## 5. Signalling Colour Architecture

Adhere to Mayer's Signalling Principle by enforcing a strict semantic colour palette across all slides, syntax badges, and status elements. Never use decorative colours arbitrarily.

* Blue (`#298DDA`): Baseline parameters, structural file inputs, and primary navigation states.
* Amber (`#F59E0B`): Exploratory search vectors, intermediate cognitive processing, and active sprint countdowns.
* Green (`#10B981`): Commercial fit, validated ledger outputs, completed code chunks, and positive criteria.
* Red (`#F5333F`): Disqualifications, negative exclusions, system halt gates, and mathematical zero-knockouts.

## 6. Disconfirmation Framing for Established Habits

When training practitioners away from intuitive defaults (such as conversational prompting) and toward deterministic architectures, apply George Posner's Conceptual Change model.

* Demonstrate Acute Failure First: Never open a module by presenting the solution as an administrative requirement. Display the direct, catastrophic failure modes of the default intuitive approach first (for example, showing how ungrounded queries output voucher scrapers and dead links).
* Induce Dissatisfaction: Force the learner to recognize the unreliability of their baseline habit before introducing the structured alternative.
* Present the Deterministic Fix: Introduce the file schema, pause gate, or mathematical formula strictly as the inevitable antidote to the demonstrated failure.
